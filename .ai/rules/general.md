# General

## Feature branches and focused commits
Use one feature/<short-kebab-case-topic> branch per feature and reuse it when continuing that feature; do not create branches for implementation subtasks. Use main for independent work and the owning feature branch for work that depends on unmerged changes; clarify the base only when genuinely unclear.
Follow the existing type: subject commit structure, with an optional scope as in fix(filament): subject. Make focused, coherent commits, stage only task files, and preserve unrelated changes; push or merge only when authorized.
